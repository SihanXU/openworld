## 2. 动画一览

| 动画 | 帧数 | 每帧时长 | 循环 | 朝向 | 播完后 |
|---|---|---|---|---|---|
| idle | 8 | 150 ms | 是 | 正面 | — |
| attack_right | 10 | 80 ms | 否 | 第 1–9 帧侧面朝右，第 10 帧正面 | 回 idle 第 1 帧 |
| attack_left | 10 | 80 ms | 否 | 第 1–9 帧侧面朝左，第 10 帧正面 | 回 idle 第 1 帧 |
| attack_down | 10 | 80 ms | 否 | 正面 | 回 idle 第 1 帧 |
| walk_down | 8 | 100 ms | 是 | 正面（朝下走） | — |
| walk_up | 8 | 100 ms | 是 | 背面（朝上走） | — |
| walk_left | 8 | 100 ms | 是 | 侧面朝左 | — |
| walk_right | 8 | 100 ms | 是 | 侧面朝右 | — |

一次完整攻击的时长是 10 × 80 = 800 ms。其中出招段（第 1–9 帧）为 720 ms，命中帧（第 6 帧）从 400 ms 开始。

attack_right 的第 1 帧会直接从正面切成侧面，第 10 帧再直接切回正面。中间没有过渡帧，这是设计上的选择，不是缺帧。

走路一个循环是 8 × 100 = 800 ms，左右脚各迈一步。

## 3. 画布与锚点（重要）

所有帧都是 **60×76 像素**，不是 60×60。

原图 60×60 的内容放在新画布的 (0, 16)，也就是在原图上方加了 16 像素透明区，用来放举过头顶的剑（attack_down 第 3–4 帧，剑尖会碰到画布顶边）。所以不要按 60×60 切图，也不要把顶部 16 像素当空白裁掉。

**锚点**（以左上角为原点的像素坐标）：

- 锚点像素是 **(30, 71)**。y = 71 是靴底那一行，x = 30 是角色中轴，也是左右镜像的对称轴。
- 所有动画、所有帧的锚点都在同一位置。播放时角色不会自带位移，位移完全由游戏逻辑控制。

**在引擎里设置 pivot 时**，建议把 pivot 放在“第 30 列像素的中心、靴底那一行的下边缘”：

| 坐标系 | pivot 值 |
|---|---|
| 像素，左上角原点 | (30.5, 72) |
| 像素，左下角原点 | (30.5, 4) |
| 归一化，左下角原点（如 Unity） | (0.5083, 0.0526)，即 30.5/60、4/76 |

pivot 的 x 必须用 30.5，不能用 30 或 0.5（= 30 像素）。偏半像素的话，镜像和正面/侧面切换时会出现 1 像素的抖动。

另外有一个已知的 1 像素差异：原画正面两只靴子不对称，正面帧的双脚中心在 x = 31，侧面帧的双脚中心在 x = 30。从正面切到侧面时，脚会横向挪 1 像素。这是已知并接受的情况，不需要在程序里补偿。

## 4. 像素渲染设置（必须）

这是像素画，任何插值或压缩都会把边缘糊掉或偏色。

- **过滤方式**：设为 Point / Nearest（Unity 的 Filter Mode = Point，Godot 的 Texture Filter = Nearest）。
- **压缩**：关闭，或用无损格式（Unity 的 Compression = None）。
- **Mipmap**：关闭。
- **缩放**：只用整数倍（×2、×3、×4…），并保证摄像机或像素对齐到整数像素，避免出现亚像素位置。
- **图集打包**：
  - 不要开 Tight 或多边形裁切。
  - 如果开了 Trim（裁掉透明边），必须保证 pivot 仍然对应原始 60×76 坐标里的 (30.5, 72)。
  - 帧之间建议留 1–2 像素 padding，防止采样到相邻帧。
- **透明**：资源只有完全透明（alpha 0）和完全不透明（alpha 255）两种像素，没有半透明。可以用 alpha test / cutout 渲染，不需要 alpha 混合。

## 5. 左右朝向

attack_left 和 walk_left 都已经做好，直接用即可。walk_left 由 walk_right 的全部 8 帧以 x = 30 为轴镜像得到，可以直接用引擎的 flipX 代替（翻转轴同样要用 pivot x = 30.5）。

以下是 attack_left 的说明：它由 attack_right 的第 1–9 帧以 x = 30 为轴（x' = 60 − x）镜像得到，第 10 帧是正面 idle，没有镜像。

如果想省资源、改用引擎的水平翻转（flipX）来播 attack_right，也可以，但要注意两点：

1. 翻转轴必须是第 2 节里的 pivot（x = 30.5），这时翻转结果和 attack_left 第 1–9 帧逐像素一致。
2. **第 10 帧不能翻**。正面原画左右不对称，翻过去会和 idle 对不上，跳一下。播到第 10 帧时要取消翻转，或者直接切到 idle 第 1 帧。

idle 和 attack_down 是正面朝向，任何时候都不要翻转。

## 6. 连击逻辑（重要）

每个攻击动画分两段，定义在 `anims.json` 里，帧号**从 0 开始**：

| 字段 | 值 | 含义 |
|---|---|---|
| `segments.main` | [0, 8] | 出招段，即第 1–9 帧 |
| `segments.recover` | [9] | 收尾段，即第 10 帧（和 idle 第 1 帧相同） |
| `hit_frame` | 5 | 命中帧，即第 6 帧 |
| `chain.at_frame` | 8 | 连击检查点，在第 9 帧播完时检查 |
| `chain.goto_frame` | 0 | 连击时跳到下一个攻击动画的这一帧 |
| `chain.can_chain_to` | attack_right / attack_left / attack_down | 允许接续的攻击动画 |

**规则**：播到 `chain.at_frame` 那一帧结束时：

- 如果有新的攻击输入（或 AI 决定继续攻击），切到目标攻击动画的 `goto_frame`，**不播 recover 段**；
- 如果没有，播 recover 段，然后进入 idle 第 1 帧。

伪代码：

```
on_frame_end(anim, frame):
    if anim.loop:
        return                                 # idle 自己循环
    if frame == anim.chain.at_frame:
        next = consume_attack_input()          # 可在 main 段任意时刻缓存输入
        if next in anim.chain.can_chain_to:
            play(next, start_frame = anims[next].chain.goto_frame)
            return
    if frame == anim.frames - 1:               # recover 段播完
        play("idle", start_frame = 0)
```

实现时要注意：

- 建议在出招段期间就开始缓存攻击输入，比如命中帧之后的输入都算数。不要只在第 9 帧那 80 ms 里检测，否则连击很难按出来。
- 不同方向之间也能直接接，比如右接左、右接下。侧面第 9 帧接正面第 1 帧，或者侧面翻成另一侧，视觉上都可以接受。
- 打断（受击、死亡等）可以在任意帧切走，资源上没有限制。

## 6.5 走路（重要）

**原地踏步**：四个走路动画本身都不带位移，角色往哪走、走多快，完全由游戏逻辑移动角色坐标来实现。pivot 和靴底行 y = 71 在所有帧都不变。

**移动速度与步频**：动画一个循环 800 ms，左右脚各迈一步。侧面走路时，着地的那只脚在 400 ms（4 帧）里从前往后移动约 15 像素（脚踝从 x≈34 移到 x≈19），所以角色移动速度约为 15 像素 / 400 ms ≈ 37 像素/秒（以 1 像素 = 1 单位计）时，脚底不会明显打滑。速度差太多时，建议按比例调整播放速度，比如移动速度翻倍就以 2 倍速播放，不要改帧。

**方向选择**：
- 四方向移动：按移动方向直接选 walk_down / walk_up / walk_left / walk_right。
- 斜向移动：没有斜向动画，建议按水平分量优先选 walk_left / walk_right；以纵向为主时再用 walk_down / walk_up，避免频繁切换。
- 停止移动：切回 idle 第 1 帧即可。走路任意一帧都可以直接切回 idle，跳变只有 1–3 像素，不需要过渡帧。

**和攻击的衔接**：走路中可以在任意帧直接切到攻击动画的第 1 帧。attack_right/left 第 1 帧是侧面，和 walk_right/left 接得最自然；attack_down 第 1 帧是正面，和 walk_down 接得最自然。攻击收尾段播完回 idle，再由移动输入切到走路。

**持剑姿势**：
- 正面（walk_down）：剑尖朝下，剑和手比 idle 抬高 3 像素，剑尖离地。
- 背面（walk_up）：剑在身前，从背后看不见。
- 侧面（walk_left / walk_right）：剑竖着举在身前，剑尖朝上。

**脚的位置**：正面和背面走路时双脚只上下抬起、不左右移动。侧面走路时两只脚会在 x = 30 前后交替移动，这是迈步动作本身的位移，整个循环平均下来脚仍在 pivot 下方，程序不需要补偿。

## 9. 与原图的关系

- **idle 和所有正面帧**：用的是原图像素，没有缩放或重采样。原图里有少量半透明像素和接近重复的颜色，已经统一处理过：alpha ≥ 128 视为不透明，其余视为透明；130 种颜色合并为 24 种基础色，单个颜色的最大偏差为 6/255，肉眼看不出。
- **attack_down 第 1–8 帧**：剑和手从身体上拆了下来，由脚本单独绘制；原来被剑挡住的罩袍用原调色板补齐了。
- **attack_right / attack_left 第 1–9 帧**：侧面图是按原图重新绘制的，身高、像素比例、调色板都与原图一致，已经经过确认。身体前倾/后仰是把身体分段做整数像素平移实现的。
- **walk_down**：原图像素。靴子和下摆分左右整段抬起，上半身整段下沉、左右偏移 1 像素；两侧披风逐行横移，越往下摆动越大（最多 2 像素），往外甩时原位置保留一份，避免和身体之间露缝。
- **walk_up**：背面图是新画的。外轮廓取自正面图的镜像，只用原调色板。走路时整块披风随步伐左右甩动（下摆最多 2 像素），平移后按新轮廓重新描边，下摆锯齿每帧横移 1 像素，表现布料波动。
- **walk_left / walk_right**：上半身用已确认的侧面图；下摆、腿和靴子按每帧参数用原调色板绘制。

## 10. 修改与重新生成

所有关键参数都在 `make_boss_anims.py` 顶部：

| 参数 | 控制内容 |
|---|---|
| `IDLE_BOB` | idle 每帧上半身下沉多少像素 |
| `IDLE_MS`、`ATTACK_MS` | 每帧时长 |
| `ATTACK_RIGHT`、`ATTACK_DOWN` | 每帧的身体倾斜、手和肘的位置、剑的角度、刀光参数 |
| `ATTACK_HIT_FRAME` | 命中帧 |
| `CHAIN_GOTO_FRAME` | 连击时跳到哪一帧。改成 1 会跳过“转身下蹲”，连击节奏更快 |
| `CHAIN_TARGETS` | 允许连击接续的动画 |
| `WALK_FRAMES`、`WALK_MS` | 走路帧数、每帧时长 |
| `WALK_FRONT` | 正面/背面走路每帧的抬脚高度、上半身下沉和左右偏移 |
| `WALK_SIDE` | 侧面走路每帧两只脚的前后位置、抬起高度、脚型、下沉、披风后飘 |
| `WALK_CAPE_SWAY`、`WALK_CAPE_TOP`、`WALK_CAPE_HEM_STEP`、`CAPE_JAG` | 正/背面走路披风每帧摆动幅度、从哪一行开始摆、背面下摆锯齿的流动速度和形状 |
| `WALK_SWORD_LIFT`、`WALK_SIDE_HAND`、`WALK_SIDE_LEAN` | 走路时剑抬高多少、侧面握剑位置、侧面前倾量 |

运行方式：

```
python make_boss_anims.py
```

运行后会覆盖本文件夹里的所有输出，并重新生成 `selfcheck.txt`。

**会影响程序接入的改动**：如果改了帧数、时长、命中帧或画布尺寸，`anims.json` 会同步更新，程序请以 json 为准，不要在代码里写死这些数字。
