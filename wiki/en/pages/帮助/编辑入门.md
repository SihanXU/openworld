Welcome to editing the OpenWorld Wiki. The wiki is written in Chinese first: the Chinese pages are the source, and this English edition is their translation. Every page is a file in the GitHub repository [SihanXU/symbolic-world](https://github.com/SihanXU/symbolic-world): a Chinese page lives under `wiki/pages/`, its English translation under `wiki/en/pages/` at the same path. Everyone on the project team can edit them. A minute or two after a change is merged into the main branch (main), the site updates by itself.

This page is about editing the English pages. How the English edition follows the Chinese one is explained in full in the last section, [[#The English edition]].

## Editing a page

1. Open the page on the site and click "Edit" at the top right. You land on GitHub's editor for this file (you need to be signed in to GitHub and be a collaborator on the repository). If the page has not been translated yet, the button says "Translate" instead: it starts the English file on GitHub with the Chinese text already in it, ready to be translated (see [[#The English edition]]).
2. Edit the text. For the format, see [[Format Manual]]; for how to write, see [[Style Guide]].
3. At the bottom of the page, write one line saying what you changed, then:
   - **Small changes** (a typo, a missing sentence, a wrong number, a better wording): choose "Commit directly to the main branch" and commit.
   - **Big changes** (rewriting a section, changing the structure, a whole new translation): choose "Create a new branch … and start a pull request", and wait for someone to look at it before it is merged.

After you commit, the repository's automatic check builds the whole wiki, both editions. If a link or a template is wrong, the check fails and tells you, in the pull request, which line is the problem. This holds for English pages too: a broken link or template in an English page fails the build, while a translation that is merely missing or out of date never does.

If what is wrong is the content itself (a fact, a number, a section that should not be there), fix the Chinese page: the English page follows it. An English page should say what its Chinese page says, no more and no less.

## Creating a page

- New pages are written in Chinese first. The English edition already has a page for every Chinese page, translated or not, so there is rarely a reason to create an English page from nothing.
- A link to a page that does not exist yet shows in red. In the English edition this usually means the Chinese page does not exist either, or the link's target is misspelled: check the target against the English title of the page you meant (or write its Chinese title, which also works).
- Every person, item, monster, location and quest in the game has a page generated for it automatically (marked as a stub). Clicking "Edit" or "Translate" on such a page creates the corresponding file; its skeleton already holds the data templates it should have, so you only add the text. A page about a game thing may be written in English before anyone writes the Chinese one: keep the `object:` line and the path the button gives, so that the Chinese page, once written at the same path, pairs with it.

## Discussion

The "Talk" tab at the top of each page lists that page's GitHub issues (labelled `wiki`, titled with the page's name), and "＋" next to it opens a new one. Discuss first, then edit, when you want to:

- change the structure or templates of a whole kind of page;
- write lore or story that has not been settled;
- delete a page or a large part of one.

Because the Chinese pages are the source, these discussions are about both editions at once. A question about a translation only (a term, a wording) can be raised on the English page.

## Previewing locally

With the dependencies installed (`npm install`), run this in the repository's root folder:

```bash
npm run wiki
```

Open `http://localhost:5180/wiki/en/` in your browser for the English edition (`http://localhost:5180/wiki/` is the Chinese one). Change a file under `wiki/en/pages/` (or `wiki/pages/`) and refresh the page to see it. If you only want to check for errors:

```bash
npm run wiki:check
```

## The generated parts

Infoboxes, tables, schedules, dialogue and recipes are read from the game's code when the wiki is built (see [[Format Manual#Data templates|data templates]]). In the English edition they come out in the game's own English: names, lines and descriptions are those the game shows when it is set to English. If they are wrong, what needs fixing is the game's code, not the wiki page. Once someone changes the game's code and commits it, the wiki updates with it.

A few words of the game's data have no English term yet; they are listed on [[Special:Completeness|Special:Completeness]] under "Missing terms", and are added to `wiki/en/terms.json`.

## Completeness

Everything in the game must have a page, and every system must be explained. The build checks this on the Chinese edition: every person, item, monster, boss, location, quest, skill branch, recipe and status in the game's data, and every key and every panel of the controls, needs a page or a section. When the game adds something and the wiki has not caught up, the build reports it.

The English edition follows the Chinese one page by page. [[Special:Completeness|Special:Completeness]] shows how far it has got: how many pages are up to date, how many are out of date and how many are not translated yet, each with its list. Pages not finished yet, and pages linked to but missing, are listed on [[Special:Stubs|Special:Stubs]].

## The English edition

The English edition (served at `/wiki/en/…`, with [中文](/wiki/) as the link to the other edition at the top of every page) is a translation of the Chinese one. Chinese is the source: the team writes in Chinese as usual, and the English pages follow.

**Where the files are.** Each English page is a file under `wiki/en/pages/` with **the same path and the same (Chinese) file name** as its Chinese page: the translation of `wiki/pages/人物/伊尔丝修女.md` is `wiki/en/pages/人物/伊尔丝修女.md`. Pages are paired by path, never by title, so never rename or move an English file on its own. A page is served at `/wiki/en/<Title>`, with spaces written as `_` (`/wiki/en/Editing_Basics`).

**Front matter.** An English file starts with its own block:

```
---
summary: The keeper of the fire in Firstlight Village's chapel.
categories: Firstlight Village
aliases: Ilse
source: 3f9a1c0b7d2e
---
```

and, for a page that is not about a game thing:

```
---
title: Satiety
summary: How full you are, and what hunger does.
source: 8c41e07a2b95
---
```

- `title:` the English title, for a page that is not about a game thing. A page about a game thing (a person, an item, a location…) takes the game's English name as its title by itself, and needs no `title:`.
- `summary:` one sentence, used in search results and lists.
- `categories:` and `aliases:` comma-separated, in English, as the Chinese page's 分类 and 别名.
- `source:` which version of the Chinese text this translates (a hash). Do not write it by hand: it is set by `npm run wiki:translate -- stamp <file>`.
- The type, the game object and the status are taken from the Chinese page; an English file does not repeat them. The one exception is a page about a game thing written in English with no Chinese file yet: it carries `object: <id>` itself.

**When the Chinese page changes.** The build compares the Chinese text with the `source:` of its translation. When they differ, the English page shows a banner saying the Chinese page has changed since the translation was made, and is listed as out of date on [[Special:Completeness|Special:Completeness]]. To bring it up to date, compare the Chinese page's history since the translation (the "History" tab on the Chinese page), change the English text to match, then stamp it again.

**Pages not translated yet.** They still exist in English. A page about a game thing shows what the game's own data says, in English (its infobox and tables); any other page shows the Chinese text. Both carry a banner and a "Translate" button that starts the English file on GitHub with the Chinese text in it. For a page that is not about a game thing, the file the button starts has `title:` set to the Chinese title: replace it with the English one. The file also already carries `source:` for the Chinese text as it is now.

**How to translate a page.**

1. Click "Translate" (or "Edit" on an out-of-date page), or copy the Chinese file to the same path under `wiki/en/pages/`.
2. Translate everything a reader reads, fully and faithfully, following the [[Style Guide]]. Keep every heading, in the same order and at the same level: sections are matched between the editions by their position, so a heading added, dropped or moved breaks the links into the page. New material goes under an existing heading, and only if the Chinese page has it too.
3. Links and template arguments may stay in Chinese (`[[露米]]`, `{{物品|木头}}`): the build finds the English page they mean. Templates have English names as well (`{{infobox}}` is `{{信息框}}`), and either name works in either edition; see [[Format Manual#Templates|templates]].
4. In the repository's root folder, run `npm run wiki:translate -- relink <file>`, then `npm run wiki:translate -- stamp <file>` (for example `npm run wiki:translate -- stamp wiki/en/pages/人物/伊尔丝修女.md`). `relink` rewrites what you left in Chinese into the English edition's own words: link targets and their `#sections`, raw `/wiki/…` addresses, template names, and the template arguments that name pages, things or keys. `stamp` records which version of the Chinese page the file translates. With no file named, both work on every English page.
5. Check the page in the local preview, then commit as in [[#Editing a page]].

**What is left to do.** `npm run wiki:translate -- status` lists the pages not translated yet and the pages out of date, each with its Chinese file; [[Special:Completeness|Special:Completeness]] shows the same on the site. None of this fails the build. What does fail it, in English pages as in Chinese ones, is a broken link, a link to a section that does not exist, or a template the build cannot run.
